## 接口与类型

- Architect 输出：`outline/outline.json`、`outline/outline.md`
- Writer 输出：`draft-vN.md`、`claims-vN.json`、`citation-map-vN.json`、`writer_notes.md`
- Editor 输出：`review-vN.json`、`review-vN.md`
- Review 阈值：overall >= 80，citation_consistency >= 90，unsupported high-risk claim 为 0。
- 已落地 API：`internal/artifacts.WriteDraftBundle`、`WriteReview`、`CommitAccepted`、`ValidateDraftArtifacts`、`ChapterState`。

## 实现要点

- Writer 每次只写一个章节或小节。
- Writer 不允许引用未确认文献；材料不足必须输出 gap。
- Editor 必须验证 claim 到 reference 的支持关系，不确定按不通过处理。
- 重写最多 2 轮；超限标记 `needs_human_review` 并继续后续章节。
- chapter 状态建议：drafting、reviewing、revision_required、accepted、needs_human_review、committed。
- 章节 commit 只接受已通过 review 的版本。

## 测试要点

- mock Writer/Editor 输出验证章节状态转换。
- 低分 review 触发 revision_required。
- 超过重写上限标记 needs_human_review 且不死循环。
- missing claims / citation map 返回结构化评审错误。
- 未确认引用 key 出现在 citation map 时评审不通过。

## 产出清单

- `internal/artifacts/paths.go`：章节产物路径生成与 chapter/version 校验。
