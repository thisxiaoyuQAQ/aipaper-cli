# BUG-20260620-01 修复：References 等列表型 TUI 屏幕一次性铺开导致超出终端、无法滚动

## 需要先读
- 项目备忘录.md
- docs/开发进度.md
- internal/tui/app/root.go（Update/View、WindowSizeMsg 转发缺失）
- internal/tui/references/view.go、model.go（核心溢出点）
- internal/tui/writing/view.go（已有的 fitLines / renderViewport / scrollbarCell 可复用范式）
- internal/tui/materials/view.go、search/view.go、exportsummary/view.go、done/model.go（同类隐患）

## Bug 摘要
- **实际表现**：文献确认页面（References）把所有候选文献一次性全部铺开，每条 5–7 行（标题 + 作者年份 + DOI/URL + 摘要 + 相关性 + 理由），候选一多就远超终端高度，TUI 顶到屏幕外无法看全，也没有滚动；长标题/摘要/理由行还会超出窗口宽度不换行。
- **期望表现**：列表按当前窗口大小自动换行；边框自动贴合窗口边界；列表区域可上下滚动（光标移动保证当前项可见），而不是一次铺满；其他列表型屏幕有同类问题一并修复。
- **复现路径**：走完 MaterialsScan → SearchProgress → 进入 References 页，候选数 × 6 行 > 终端行数。
- **影响范围**：
  - References（核心）：整个 `visible` 列表塞进单个 `referencesPanelStyle.Render(...)`，无高度限制、无换行、无滚动。
  - RootModel：从不把 `tea.WindowSizeMsg` 转发给 References/Materials/Search/ExportSummary/Done（只有 Writing 自己接了），这些模型都不存宽高。
  - 同类隐患：Materials `details` 明细列表、SearchComplete 错误列表、ExportSummary 输出/问题列表，内容多时同样可能溢出且都不换行。

## 根因假设
- **假设 1（已确认）**：References `View()` 把全部 `visible` 候选逐条拼进一个 panel，再用 `referencesPanelStyle.Render(panel.String())` 一次性渲染，panel 没有高度上限，lipgloss 会原样输出全部行。
  - 证据：`internal/tui/references/view.go:79-111` 循环 `range visible` 全量输出，无截断、无 offset。
- **假设 2（已确认）**：RootModel `Update` 没有处理 `tea.WindowSizeMsg`，各屏幕模型（除 Writing）都不持有 width/height，因此无法做按窗口换行与视口裁剪。
  - 证据：`internal/tui/app/root.go` 的 `Update` switch 里无 `tea.WindowSizeMsg` 分支；references/materials/search/exportsummary/done 的 Model 结构体均无 width/height 字段。
- **假设 3（已确认）**：行内长文本（标题/摘要/理由）未做按宽换行，长字符串会撑破边框。
  - 证据：references/view.go 直接 `fmt.Fprintf` 输出 `candidate.Title` / `summary` / `candidate.RelevanceReason`，未调用类似 writing 的 `ansi.Wrap`。

## 选定方案
- **方案：全面修复（用户选定）**
  1. RootModel 在 `Update` 中接 `tea.WindowSizeMsg`，记录全屏 width/height，并把宽高注入当前活动屏幕模型（References/Materials/Search/ExportSummary/Done），保留 Writing 已有逻辑。
  2. 抽取一个轻量共享渲染工具（放 `internal/tui/ui` 或 references 包内私有），提供：
     - `wrapCells(s, width)` 按 cell 宽换行（复用 `github.com/charmbracelet/x/ansi` 的 `Wrap`/`Truncate`/`StringWidth`，与 writing 一致）。
     - `clampVisible(lines, height, offset)` 视口裁剪。
     - `cursorFollowOffset(cursor, itemHeights, viewportHeight)` 计算 offset 保证光标项可见。
  3. References：标题/摘要/理由等长行按内宽换行；列表区按「窗口高度 - 标题/提示行」计算可见行数，光标移动时自动滚动保证当前项可见；末尾常驻 footer 提示；panel 边框宽度贴窗（width - 留边）。复用 writing 的 scrollbar 思路（可选轻量指示）。
  4. Materials（details 明细）、ExportSummary（输出/问题）、Done（输出）、Search（错误列表）：接入 `wrapCells` 按宽换行；panel 按窗口宽度自适应。这些页面内容有界，不做纵向滚动视口（避免引入无谓复杂度），仅在宽度方向换行即可消除溢出。
  5. 兼容旧测试：模型零值 width/height 时回退到原渲染（或固定 80×24 默认），保证现有 `View()` 字符串断言不破；必要时更新断言以反映换行行为。
- **改动范围**：
  - `internal/tui/app/root.go`：新增 WindowSizeMsg 处理 + 注入宽高。
  - `internal/tui/references/{model,view}.go`：新增 width/height 字段、`SetSize`、视口 offset、换行渲染。
  - 共享换行/视口工具（新文件，或直接复用 writing 已有函数提取）。
  - `internal/tui/{materials,search,exportsummary,done}/view.go`：换行 + 贴宽。
  - 受影响单测：references/materials/search/exportsummary/done 的 View 断言与 root 的 Update 断言。
- **风险点**：
  - 既有 View 测试多为精确字符串断言，换行后会变化，需同步更新（不是迁就测试，而是反映新行为）。
  - Windows 终端宽度探测由 bubbletea 自动处理，无需特殊兼容；但双击窗口极窄时需保证最小可用宽度不崩。
  - References 走 `UpdateKey(string)` 接口，视口 offset 必须存进 Model 且随光标 key 自动调整。

  - `internal/tui/materials/{model,view}.go`：新增 `SetSize`，明细行按宽换行。
  - `internal/tui/search/{model,view}.go`：新增 `SetSize`，面板内容按宽换行 + 边框贴宽。

  - `internal/tui/done/{model,model.go(view)}`：新增 `SetSize`，整页按宽换行。

- **验证**：`go build ./...`、`go test ./...`、`go build -o aipaper-cli.exe ./cmd/aipaper-cli` 均通过。
- **剩余风险**：
  - 真实终端交互（窄窗、CJK 宽字符、resize 抖动）未在本机实跑，建议用户在 TUI 中验收 References 滚动与换行效果。
  - ConfigWizard/Requirements/RecoverPrompt 为表单/提示型屏幕，未纳入视口改造（非列表型，按方案范围不在内）；如后续表单字段超长可按同套 `ui.WrapCells` 扩展。
  - 视口按候选块整体滚动（保证每条完整可见），单个候选高于可用高度时仍可能占满窗口——属可接受折中。
