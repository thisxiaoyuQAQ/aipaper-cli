# 项目需求

> 来源：本文件由《2026-06-05-aipaper-cli-design.md》（状态：已批准）提炼为结构化需求。
> 设计文档为唯一权威来源，本文件用于开发阶段快速对照。

## 1. 产品定位

`aipaper-cli` 是一个面向**学术综述 / 文献综述**的 AI Agent CLI。第一版（MVP）不追求成为完整论文管理平台，而是稳定跑通核心闭环：

> 用户通过 TUI 填写结构化写作需求，系统结合用户材料与联网学术搜索，经人工确认文献后，由多 Agent（Architect / Writer / Editor）自动规划、写作、评审、重写，输出结构化论文项目目录。

设计核心原则：**LLM 驱动，Host 服务**。流程决策全部由 Coordinator（主 Agent）承担，Host / 代码只负责可靠执行、持久化、恢复与展示。

---

## 2. 功能需求

### F1 配置与启动引导
- 首次运行进入 Provider 引导：Provider / API Key / Base URL / Model / 默认语言 / 引用格式。
- 配置写入 `~/.aipaper/config.json`，项目级可选覆盖 `./aipaper.json`，命令行 `--config` 最高优先级。
- 支持 Provider：`openrouter` / `anthropic` / `gemini` / `openai` / `deepseek` / `qwen` / `glm` / `grok` / `ollama` / `bedrock` / 自定义代理。
- `ollama` / `bedrock` / 显式 `type` 的自定义代理允许 `api_key` 为空。
- 用户故事：作为新用户，我能在首次运行时被引导完成最小可用配置，无需手写 JSON。

### F2 结构化需求表单
- TUI 表单收集：主题、研究问题、综述范围、目标语言（zh-CN / en）、引用格式（GB/T 7714 / APA）、目标字数、材料目录、是否允许联网搜索、搜索增强源配置、章节偏好/特殊要求。
- 提交后写入 `requirements.json`。
- 用户故事：作为作者，我能用表单一次性提供完整写作约束，系统据此驱动全流程。

### F3 材料解析
- 完整支持：PDF、Markdown、TXT、BibTeX。
- 基础 / 降级支持：DOCX、网页链接、CSV（必须显式标注"降级提取"）。
- 扫描材料目录生成 `materials/manifest.json`，每个材料有稳定 ID（`material_001` …）。
- BibTeX 直接进入候选文献池，默认标记来自用户材料。
- 用户故事：作为作者，我能把已有 PDF/笔记/参考文献丢进一个目录，系统自动解析为可追踪的事实层。

### F4 学术搜索
- 内置免费公开源：Semantic Scholar、Crossref、arXiv、PubMed。
- 可选增强源（配置启用）：SerpAPI、Tavily、Exa、Google Scholar 代理、自定义 provider。
- 字段标准化：title / authors / year / DOI / URL / abstract / venue / source / citation_count / relevance_score。
- 去重：DOI 优先 → URL → title+author+year hash 兜底。
- 产出 `references/candidates.json` 与 `candidates.md`。

### F5 文献人工确认（硬性步骤）
- TUI 多选列表展示候选文献及摘要信息、相关性理由、去重信息、系统建议。
- 交互键：Space 选/取消、Enter 确认、`/` 搜索、`s` 排序、`a` 全选高相关、`r` 标记拒绝、`q` 返回。
- 确认后写入 `references/confirmed.json` / `rejected.json` / `confirmed.bib`。
- **只有 confirmed references 可用于正文引用**，未确认文献严禁引用。

### F6 大纲规划（Architect）
- 基于需求与确认文献生成 `outline.json` / `outline.md`。
- 含：标题建议、摘要目标、章节列表、每章写作目标/关键问题/应引用文献群、章节逻辑关系、字数分配、需 Writer 避免的重复点。

### F7 章节写作（Writer）
- 每次只写一个章节/小节，产出 `draft.md` / `claims.json` / `citation_map.json` / `writer_notes.md`。
- 不允许引用未确认文献；材料不足必须显式标记 gap，禁止编造来源。

### F8 质量门控（Editor）
- 产出 `review.json` / `review.md`：总分、结构逻辑、引用一致性、综述完整度、可读性评分，unsupported claim 列表，required/optional fixes。
- 通过阈值：单章总分 ≥ 80、引用一致性 ≥ 90、无高风险 unsupported claim。
- 重写上限 2 轮；超限标记 `needs_human_review`，不中断整篇流程。

### F9 引用一致性（硬门槛）
- 正文关键论断必须出现在 `claims.json`，且每个论断映射至少一篇确认文献。
- Editor 必须核验文献是否真的支持论断；不确定按不通过处理。
- 禁止"研究表明""大量文献指出"等无来源泛化表达。
- 最终输出 `final/citation-trace.json` 保留 claim → reference 追踪。

### F10 输出与导出
- `final/paper.md`（Markdown 主稿）、`final/paper.docx`（可交付初稿）、`references.md`、`citation-trace.json`、`report.md`。
- Docx 不承诺复杂模板、自动目录、脚注等高级排版。
- 引用格式化失败不阻塞正文生成，但须在 report 中列出。

### F11 运行进度观察（TUI）
- 展示：当前阶段、章节、当前 agent、当前工具调用、已完成章节、重写轮次、最近错误、token/cost 估算、checkpoint step、输出路径。
- 首版不支持强实时 Steer；仅支持查看日志、安全停止、等当前 Step 完成后退出、下次从 checkpoint 恢复。

### F12 Step 级断点恢复
- 每个工具成功后写入 step checkpoint + latest.json + progress.json。
- 同一目录再次启动：校验 latest checkpoint 指向 artifact 的存在与哈希 → 生成恢复 prompt → Coordinator 续跑。
- 幂等：同 `chapter_id + draft_version` 不无提示覆盖，已存在且哈希匹配返回 `already_exists`，不匹配返回冲突错误。

## 3. 配置项清单

| 配置项 | 默认值 | 取值范围 | 说明 |
|---|---|---|---|
| provider | 无（引导填写） | 见 F1 列表 | LLM provider |
| model | 无（引导填写） | provider 官方模型 ID | 不自动改写模型 ID |
| default_language | zh-CN | zh-CN / en | 默认写作语言 |
| citation_style | gbt7714 | gbt7714 / apa | 中文默认 GB/T 7714，英文默认 APA |
| target_words | 8000 | > 0 | 目标字数 |
| allow_online_search | true | bool | 是否允许联网学术搜索 |
| search_providers | [] | 见 F4 增强源 | 启用的可选增强源 |
| 重写上限 | 2 | 固定 | 超限标记 needs_human_review |
| 章节总分阈值 | 80 | 0-100 | 单章通过门槛 |
| 引用一致性阈值 | 90 | 0-100 | 引用门槛 |

## 4. 数据范围与存储策略

- 数据量级：单论文项目 8000 字量级，材料数十篇、候选文献数十至数百条、章节 ≤ ~10。
- 存储：首版以**文件系统**作为 Store，所有产物落在 `{cwd}/output/aipaper/` 下。
- 写入：temp + fsync + rename 原子写入；JSON 可独立校验；checkpoint 只记录 artifact 路径与哈希，不塞长正文。
- 项目绑定启动目录：换目录 = 换一篇；回到原目录 = 自动从最近 checkpoint 恢复。
- 全局配置 `~/.aipaper/config.json` 跨项目共享。

---

## 5. 目标性能

- 单 Step（工具调用）应在合理超时内完成；外部搜索超时默认 30s。
- 可重试外部错误（搜索超时、LLM 临时错误、导出临时失败）重试 2-3 次。
- 并发：首版以单 Run 串行流程为主，搜索可并发调用多数据源。
- 崩溃一致性：任意点崩溃后可通过 latest checkpoint + artifact 哈希判断可恢复位置。

## 7. 非功能需求

- **安全性**：API Key 不落入日志与事件流（CLI `config` 命令已做 redact）；输入路径校验，artifact 路径必须相对且不逃逸 store root；联网文献必须用户确认后方可引用。
- **可观测性**：单一事件流驱动 TUI；run.json 记录运行元信息与事件；report.md 汇总质量/风险/待人工复核项。
- **可恢复性**：Step 级 checkpoint，崩溃后精确恢复到下一个预期 step。
- **结构化错误**：工具错误返回 `{ok:false, error:{code,message,retryable,details}}`，不只给自然语言。

---

## 8. 环境要求

- 开发环境：Go 1.25+。
- 环境变量（详见 `.env.example`）：各 provider 的 API Key（如 `OPENROUTER_API_KEY`、`OPENAI_API_KEY` 等），可选搜索增强源 key（`SERPAPI_KEY`、`TAVILY_KEY`、`EXA_KEY` 等）。
- 容器化：首版不强制，可选提供 Dockerfile（非 MVP 范围）。

---

## 9. 明确不做（首版边界）

- 强实时 Steer 干预（写作中即时改方向）。
- 完整论文管理平台（多项目仪表盘、云同步、协作）。
- 精细 Word 排版（复杂模板、自动目录、脚注）。
- 全格式深度解析（DOCX/URL/CSV 仅基础/降级）。
- 全自动无确认引用（联网结果必须用户确认）。
- OCR 扫描 PDF、表格/图片/公式深度理解、Google Scholar 原生稳定抓取、自动判断文献真实性。

---

## 10. 成功标准（验收）

1. **流程闭环**：TUI 表单 → 最终输出目录完整跑通，无需人工改中间 JSON，文献确认为必经步骤。
2. **质量门控**：Editor 评审 JSON 结构稳定，低于阈值触发重写，unsupported claim 被记录，超限不死循环。
3. **引用追踪**：Writer 不用未确认文献，每章有 claims + citation map，最终有 citation trace，参考文献可导出 Markdown + BibTeX。
4. **恢复能力**：每个关键 step 有 checkpoint，latest 可校验 artifact hash，崩溃后能恢复到下一个预期 step，已完成 artifact 不被重复覆盖。
5. **TUI 可用性**：首次配置可完成，文献候选可多选确认，写作进度可观察，错误可读。
6. **输出可用**：paper.md 可读、paper.docx 可打开、report.md 说明质量/风险/待人工复核，结构化目录可追踪写作过程。
