## Bug 摘要

- 实际表现：TUI 到 WritingProgress 后无任何真实写作；`writing.Model.Init()` 返回 nil；
  `app.NewAgentRuntime` 全历史无 TUI/CLI 调用点；`writer_run` runner 是 "not implemented" 桩。
- 期望表现：WritingProgress 启动真实 Host/AgentRuntime，Coordinator 经工具驱动全流程，
  流式/usage/章节事件入四区布局，Ctrl+C 两阶段停止可中断真实运行，恢复 prompt 注入生效。
- 复现路径：配置真实 provider → TUI 走到 WritingProgress → 停在 "Initializing"，零 LLM 调用。
- 影响范围：仅真实运行路径；mock 测试、恢复、导出、质量引擎不受影响（模块 31 已验证）。
- 根因（已定位）：模块 22 接线工作未实际落代码，进度文档记为已完成（文档与代码不符）。

## 已核实的事实（本次验收期间确认，可直接信任）

- agentcore v1.6.11 Agent API：`Prompt(string)` 启动、`Continue()` 续轮、`WaitForIdle()`、
  `Abort()`/`AbortSilent()`、`Steer(msg)`、`Subscribe(func(Event))`、`State()`、`UserMsg(text)`。
- ChatModel 接口：`Generate(ctx, []Message, []ToolSpec, ...CallOption)`、`GenerateStream(...)`；
  `Message.TextContent()` 取文本，`Message.Usage` 有 token 计数。

  `Type:"openai"` + BaseURL 带 `/v1`）已经 `tools/real-before-after` 用 gpt-5.5 实跑验证。
- 真实渠道：用户提供 newapi（`https://api.smmmc.cn/v1`，模型 gpt-5.5），密钥**只经环境变量
  `SMOKE_API_KEY` 注入**，严禁写入任何落盘文件/git（密钥卫生教训已记验收报告遗留事项 4）。

调度；流式输出、usage 统计、steering、停止、恢复全部接通 TUI。

### 风险点

- Coordinator 自治多轮链路对模型能力敏感：步骤多（outline→evidence→plan→每章 write/extract/verify/review→export），
  续轮策略（B4）是关键；真实冒烟若发现模型不守工具协议，优先调 Coordinator kickoff 文案而非改 Host 规则。
- 勿动约束：`internal/agent/` 决策规则、`internal/tui/writing/` 核心逻辑、quality 全家桶只消费；
  所有新增都走边界文件。
- 验证未过 2 次 → 停下向用户列方向（参照 Bug修复 skill 卡住处理）。
