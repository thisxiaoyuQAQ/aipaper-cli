# 09-E2E验收与测试夹具

## 模块做啥（1 行）

建立 mock LLM 和小型材料 fixture，验证 MVP 全流程、恢复能力和关键验收标准。

## 依赖谁（1 行）

- 必须先完成：vault/02-材料解析与索引.md、vault/03-学术搜索与文献候选.md、vault/04-文献确认TUI.md、vault/05-Agent运行时与Coordinator.md、vault/06-写作产物与质量门控.md、vault/07-StepCheckpoint恢复.md、vault/08-最终导出与报告.md
- 可并行：无

## 需要先读哪几个文件（2~5 个）

- 项目备忘录.md
- docs/需求与架构.md「首版边界」「CLI 接口速查」
- docs/开发进度.md
- docs/superpowers/specs/2026-06-05-aipaper-cli-design.md「测试、验收标准与首版边界」

## 接口与类型

- fixture 目录：`fixtures/review-mini/materials/`
- mock LLM 响应：需求到大纲、章节草稿、评审通过/不通过、重写通过。
- E2E 断言：final artifacts、checkpoint、progress、report、citation trace。
- 已落地测试入口：`go test ./internal/e2e -run TestE2EReviewMini`

## 实现要点

- fixture 至少包含 `paper1.md`、`paper2.bib`、`notes.txt`。
- E2E 不依赖真实网络和真实 LLM。
- 测试需覆盖新建 run、材料解析、候选文献、人工确认模拟、写作、评审、重写、导出。
- 中途模拟 kill / restart，验证 latest checkpoint 可恢复到下一预期 step。
- 验收失败时输出清晰的 artifact 路径和差异。

## 测试要点

- `go test ./...` 必须通过。
- E2E 可使用 `go test ./internal/... -run TestE2EReviewMini` 或独立包测试。
- 验证 `final/paper.md` 可读、`final/report.md` 包含质量和风险说明。
- 验证没有未确认引用进入 final artifacts。

## 产出清单

- `fixtures/review-mini/materials/paper1.md`
- `fixtures/review-mini/materials/paper2.bib`
- `fixtures/review-mini/materials/notes.txt`
- `internal/e2e/review_mini_test.go`：串联 bootstrap、材料解析、mock search、人工确认模拟、mock Writer/Editor、重写、accepted commit、mid-run recover、final export 和 checkpoint 校验。

## 行数预估

- fixture 小而稳定；E2E 测试拆 helper，避免单文件过长。
