# 02-材料解析与索引

## 模块做啥（1 行）

扫描材料目录，解析支持格式，生成可追踪的 `materials/manifest.json`、提取文本和元数据。

## 依赖谁（1 行）

- 必须先完成：vault/01-基础脚手架与配置Store.md
- 可并行：vault/03-学术搜索与文献候选.md

## 需要先读哪几个文件（2~5 个）

- 项目备忘录.md
- docs/需求与架构.md「核心功能」「输出目录契约」
- docs/interfaces/materials.md
- internal/contracts/types.go
- internal/store/*.go

## 接口与类型

- `MaterialManifest{Items []MaterialItem}`
- `MaterialItem{id,path,kind,status,parser,degraded,output_text,output_meta,error}`
- 输出路径：`materials/manifest.json`、`materials/extracted/<id>.md`、`materials/parsed/<id>.json`

## 实现要点

- 完整支持 PDF、Markdown、TXT、BibTeX。
- DOCX、URL、CSV 只做基础 / 降级支持，并在 `degraded=true` 和 UI 提示中明确标注。
- 每个材料分配稳定 ID，重复扫描时尽量保持可预测顺序。
- BibTeX 解析出的条目要能交给文献候选池，标记来源为用户材料。
- 长文本按后续 Agent 可消费的粒度分块，保留来源路径和位置。
- 所有 artifact 写入必须走 `store.WriteFile` / `WriteJSON`。

## 测试要点

- 使用 fixture 覆盖 Markdown、TXT、BibTeX。
- PDF/DOCX/URL/CSV 可先用接口层 mock，真实解析库接入后补集成测试。
- 材料目录不存在、空目录、混合成功失败文件都要返回结构化结果。
- 降级格式必须在 manifest 中标记 `degraded=true`。

## 产出清单

- internal/materials/
- internal/references/ 的 BibTeX 候选入口（如拆分）
- fixtures/materials/
- 对应 `*_test.go`

## 行数预估

- 单个 parser 文件目标 < 500 行；复杂格式按 parser 拆分。
