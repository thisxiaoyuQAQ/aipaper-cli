# 12-启动状态探测与恢复入口

## 模块概述

实现 TUI 启动时的状态探测和恢复提示：根据配置、requirements、材料、候选文献、确认文献、checkpoint、final 输出判断进入哪个屏幕；检测到 valid 未完成 checkpoint 时允许继续、重新开始或退出。

## 前置依赖

- 依赖模块：07-StepCheckpoint恢复、10-无参数TUI启动与RootModel骨架、11-ConfigWizard配置向导
- 可并行模块：13-Requirements屏幕桥接与落盘（桥接代码可准备，状态探测接入需等本模块）

## 实现要求

- 新增 `internal/tui/app/state_probe.go`。
- 探测顺序必须与增量架构一致：配置 → checkpoint → requirements → materials → candidates/confirmed refs → writing artifacts → final outputs。
- 配置缺失或 role/provider 不可解析时进入 `ConfigWizard`。
- valid checkpoint 且 run 未完成时进入 `RecoverPrompt`。
- 继续恢复时调用 `app.Recover` 获取 recovery prompt，并传递给 WritingProgress runtime options。
- 重新开始路径必须二次确认；本模块只实现提示和意图，不擅自删除或清空产物。
- invalid checkpoint 应展示可读提示，并进入可修复屏幕或退出，不破坏已有产物。

## 测试要求

- 空项目进入 ConfigWizard。
- 配置完整但缺 requirements 进入 Requirements。
- 有 requirements 但缺 materials manifest 进入 MaterialsScan。
- 有 candidates 但缺 confirmed refs 进入 References。
- valid checkpoint 进入 RecoverPrompt。
- final outputs 完整进入 Done。
- invalid checkpoint 不触发继续恢复。
