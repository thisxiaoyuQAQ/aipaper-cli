# 需求与架构

## 项目定位

`aipaper-cli` 是一个面向学术综述 / 文献综述写作的 AI Agent CLI。MVP 目标是稳定跑通 TUI 需求收集、材料解析、学术搜索、人工确认文献、Agent 写作评审、Step checkpoint 恢复和最终导出的闭环。增量目标是在运行时内置论文质量 Skill 策略，把叙事契约、证据深度、claim 支撑度、审稿式修改和人工复核提示应用到写作全过程。

## 核心功能

- 配置与启动引导：首次运行收集 provider、API key、base URL、model、默认语言和引用格式。
- 结构化需求表单：收集主题、研究问题、综述范围、语言、引用格式、目标字数、材料目录、搜索开关和章节偏好。
- 材料解析：完整支持 PDF、Markdown、TXT、BibTeX；基础 / 降级支持 DOCX、网页链接、CSV。
- 学术搜索：内置 Semantic Scholar、Crossref、arXiv、PubMed；可选 SerpAPI、Tavily、Exa、Google Scholar 代理和自定义源。
- 文献人工确认：候选文献必须由用户多选确认后才进入 `references/confirmed.json`。
- Agent 写作流程：Coordinator 调度 Architect 生成大纲、Writer 生成章节、Editor 做引用一致性和质量门控。
- Quality Engine：在 enhanced/strict 路径生成 EvidenceTable、SectionQualityPlan、ClaimGraph、VerificationResult 和 QualityReport，确保 claim、evidence、reference 可追踪。
- 论文质量 Skill 运行时策略：将 `docs/skills/paper-cli-paper-quality` 蒸馏内容本地化为运行时 policy，注入 Architect、Writer、Verifier、Editor 和 QualityReport。
- Step 级恢复：每个关键工具成功后写 checkpoint、latest 和 progress，崩溃后可从最新一致 checkpoint 恢复。
- 导出与报告：输出 `paper.md`、`paper.docx`、`references.md`、`citation-trace.json`、`report.md`。

## 技术栈

- 语言/框架：Go 1.25，标准库优先。
- Agent 内核：`github.com/voocel/agentcore`，用于 Agent loop、事件流、SubAgent、ContextManager。
- LLM 适配：`github.com/voocel/litellm`，用于多 provider 模型调用。
- TUI：Bubble Tea、Bubbles、Lip Gloss。
- 存储：本地文件系统，Store 根为 `output/aipaper/`。
- 文档权威来源：`docs/superpowers/specs/2026-06-05-aipaper-cli-design.md`。

## 核心约定

- ID 策略：run 使用 `run-<UTC timestamp>`；材料 ID 用 `material_001`；候选文献 ID 用 `cand_001`；引用 key 用 `firstAuthorYearShortTitle`，冲突时追加后缀。
- 时间格式：Go `time.Time` 序列化为 RFC3339 UTC。
- 错误处理：工具错误返回 `{ok:false,error:{code,message,retryable,details}}`；Editor 不通过属于质量门控，不属于系统错误。
- 日志与事件：Host 将 agentcore 事件投影给 TUI，并可追加进 `run.json.events`；API key 必须 redact。
- 路径约束：checkpoint `outputs[].path` 必须是 Store 根下相对路径，不允许绝对路径或目录逃逸。
- 写入约束：artifact 先 temp + fsync + rename，再写 step checkpoint、latest、progress。
- 引用约束：Writer 和 Editor 只能读取 confirmed references；禁止使用未确认联网文献。
- 质量阈值：单章总分 >= 80，引用一致性 >= 90，无高风险 unsupported claim，最多重写 2 轮。
- 论文质量策略约束：运行时不直接读取外部 skill 文档，而是使用本地化 `PaperQualityPolicy`；证据不足必须进入 gaps、writer_notes 或 human review，不得成为正文主体。

## 系统结构

```text
cmd/aipaper-cli/          CLI 入口
internal/cli/             命令解析：init/status/recover/config，后续接入 TUI 启动入口
internal/app/             应用 bootstrap、Store 初始化、progress 读取
internal/config/          全局/项目/显式配置加载、合并、校验、redact
internal/contracts/       结构化 JSON 契约：需求、run、progress、材料、文献、claims、review
internal/store/           Store 路径、原子写入、哈希、布局创建
internal/checkpoint/      Step checkpoint 记录、latest 校验、恢复事实读取
internal/materials/       材料扫描、解析、manifest 写入
internal/search/          学术搜索 provider、标准化、去重
internal/references/      候选/确认/拒绝文献、BibTeX、reference key
internal/agent/           Coordinator、Architect、Writer、Editor prompt 与工具桥接
internal/quality/         Evidence、SectionPlan、ClaimGraph、Verification、Gate、PaperQualityPolicy
internal/tui/             表单、文献确认、进度观察、完成页
internal/export/          Markdown 汇总、Docx 导出、报告与引用追踪
fixtures/review-mini/     E2E 冒烟测试材料
```

## 模块职责

- TUI：收集用户输入、展示候选文献、展示进度和结果，不直接改写正文 artifact。
- Host：加载配置、创建 model/Agent、注册工具、投影事件、生成恢复 prompt、处理退出。
- Coordinator：唯一流程决策者，基于工具 JSON 事实规划、搜索、确认、写作、评审、导出。
- Architect：输出 `outline.json` 和 `outline.md`，并在质量路径中生成 EvidenceTable 与 SectionQualityPlan。
- Writer：输出章节 `draft.md`、`claims.json`、`citation-map.json`、`writer_notes.md`；必须遵守 evidence-grounded writing 策略。
- Editor：输出 `review.json`、`review.md`，承担 claim verification、审稿式 rewrite instructions 和章节质量门控。
- Tools：只返回事实 JSON，不夹带调度建议。

## 数据模型

- `Requirements`：写作需求，落盘到 `requirements.json`。
- `Run` / `RunEvent`：运行元信息和事件记录，落盘到 `run.json`。
- `Progress`：当前阶段、step、章节进度和状态，落盘到 `progress.json`。
- `MaterialManifest` / `MaterialItem`：材料扫描与解析结果，落盘到 `materials/manifest.json`。
- `ReferenceCandidate`：候选文献，落盘到 `references/candidates.json`。
- `ConfirmedReference`：用户确认文献，落盘到 `references/confirmed.json`。
- `ClaimsFile` / `CitationMap`：章节论断与引用映射。
- `Review`：Editor 评分、unsupported claims、修复项、结构化 rewrite instructions 和通过状态。
- `Checkpoint` / `OutputArtifact` / `Validation`：Step 恢复和 artifact 哈希校验。

## CLI 接口速查

| 命令 | 说明 |
|---|---|
| `aipaper-cli init [--workdir DIR] [--config FILE]` | 初始化 Store 布局和运行元信息 |
| `aipaper-cli status [--workdir DIR]` | 输出当前 `progress.json` 或未初始化状态 |
| `aipaper-cli recover [--workdir DIR]` | 校验 latest checkpoint 是否可恢复 |
| `aipaper-cli config [--workdir DIR] [--config FILE]` | 输出合并后的配置，敏感 key 已 redact |

## 部署与环境

- 本地开发：`go test ./...`
- 本地运行：`go run ./cmd/aipaper-cli --help`
- 环境模板：`.env.example`
- 全局配置：`~/.aipaper/config.json`
- 项目级配置：`./aipaper.json`
- 容器化：MVP 不强制，后续可补 Dockerfile。

## 首版边界

- 不承诺生成可直接投稿的终稿。
- 不承诺完美 GB/T 7714 / APA 格式和 Word 高级排版。
- 不做实时中断正在运行的 Agent 后立即改方向。
- 不做多用户、多项目管理后台、云同步或远程任务队列。
- 不做 OCR 扫描 PDF、表格/图片/公式深度理解。
- 联网文献真实性仍由用户确认，系统不自动背书。
